# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in a public GitHub Issue, pull request, or discussion.

Report a suspected vulnerability privately to the WTC maintainer by direct message to **@Yamabiko** in the [Making WordPress Slack](https://make.wordpress.org/chat/).

Include enough information to understand and reproduce the issue, but do not include secrets or unrelated personal data.

## Supported scope

Security reports are accepted for the current code on the repository's `main` branch and for behavior within WTC's current product scope.

WTC v1 processes PO files in the browser and does not upload translation files to a WTC server. Reports should be based on behavior that exists in the current repository rather than hypothetical hosted services or release infrastructure.

## What is not a security report

General bugs, translation-rule questions, false positives or false negatives, usability requests, and feature proposals should use normal [GitHub Issues](https://github.com/YamabikoLab/wp-translation-checker/issues).
