# WP Japanese Translation Checker v1 requirements

## Purpose

WP Japanese Translation Checker（WJTC）は、WordPress 日本語翻訳スタイルガイドのうち、機械的に判定可能な項目を `.po` ファイルに対して確認し、翻訳を提出する前に修正候補を把握できるようにする。

WJTC は WordPress 日本語翻訳スタイルガイドそのものを置き換えるものではない。

ツールの判定だけで翻訳の正しさを決定するのではなく、各指摘から判定理由とスタイルガイド上の根拠を確認できることを重視する。

## v1 scope

v1 は、日本語固有の翻訳スタイルのうち、機械判定による誤検出を抑えやすい項目を対象とする。

初期対象候補は以下とする。

- 日本語の句読点
- 英数字・記号の半角表記
- 半角文字と全角文字の間のスペース
- 半角丸括弧と前後スペース
- 丸括弧内側の不要スペース
- 括弧内末尾の句点
- 文末括弧と句点の位置
- 半角数字前後の不要スペース
- 「下さい / 全て / 既に」などの推奨表記

実際に v1 で有効にするルールは、WordPress 日本語翻訳スタイルガイドを根拠として個別に定義する。

## Locale scope

v1 では、日本語（`ja`）の翻訳スタイルのみを確認対象とする。

WJTC は将来、日本語以外の翻訳ロケールに対応する可能性を想定する。ただし、他のロケールのチェックルールおよび利用者によるロケール選択は v1 の対象外とする。

## Severity

WJTC は、指摘の確実性を区別できなければならない。

### Error

機械的に高い確度で問題と判断できる指摘。

### Warning

例外または文脈によって正しい可能性があり、人による確認が必要な指摘。

Warning は Error と同等の確実性を持つ指摘として扱わない。

## Functional requirements

### FR-01: PO file validation

**What**

利用者は `.po` ファイルを WJTC で確認できなければならない。

**Why**

WordPress の翻訳を提出する前に、実際の翻訳ファイルを対象としてスタイル上の問題を確認できるようにするため。

### FR-02: Invalid input feedback

**What**

入力されたファイルを正常に確認できない場合、利用者は確認を実行できなかったことを認識できなければならない。

**Why**

解析できなかったファイルを問題のない翻訳ファイルと誤認することを防ぐため。

### FR-03: Supported Japanese style checks

**What**

WJTC は、v1 の対象として定義された日本語翻訳スタイルのルールについて翻訳を確認できなければならない。

**Why**

提出前に機械的に発見可能なスタイル上の問題を見つけられるようにするため。

### FR-04: Validation result summary

**What**

確認完了後、利用者は確認結果の全体像を把握できなければならない。

少なくとも以下を把握できること。

- 確認が完了したか
- Error の件数
- Warning の件数
- 問題が検出されなかったか

**Why**

個々の指摘を読む前に、翻訳ファイル全体の状態を短時間で判断できるようにするため。

### FR-05: Individual finding identification

**What**

検出された各指摘について、利用者は対象となった翻訳箇所を特定できなければならない。

**Why**

利用者が `.po` ファイル内のどの翻訳を確認または修正すればよいか判断できるようにするため。

### FR-06: Finding explanation

**What**

各指摘について、利用者は以下を理解できなければならない。

- 何が問題として検出されたか
- Error または Warning のどちらであるか
- なぜ指摘されたか

**Why**

単に問題があると通知するだけでなく、利用者自身が修正の必要性を判断できるようにするため。

### FR-07: Style guide traceability

**What**

各チェックルールは、その判断根拠となる WordPress 日本語翻訳スタイルガイドの項目を確認できなければならない。

**Why**

WJTC 独自の判断ではなく、スタイルガイドを一次情報として確認できるようにするため。

### FR-08: Clear successful result

**What**

問題が検出されなかった場合、そのことを利用者が明確に認識できなければならない。

**Why**

結果が何も表示されない状態と、正常に確認した結果として問題がなかった状態を区別できるようにするため。

### FR-09: Validation report export

**What**

利用者は、確認結果を後から参照または共有できる形でエクスポートできなければならない。

エクスポートされる結果には、少なくとも以下の情報が含まれなければならない。

- 確認結果の概要
- Error と Warning
- 各指摘の対象
- 各指摘の理由
- 各指摘に対応するルール

**Why**

WJTC の画面を閉じた後でも確認結果を利用でき、翻訳の修正やレビューに活用できるようにするため。

### FR-10: Correctable finding distinction

**What**

WJTC が安全に一意の修正を決定できる指摘と、人による判断が必要な指摘を区別できなければならない。

**Why**

機械的に安全な修正と、文脈を考慮して利用者自身が判断すべき変更を混同しないため。

### FR-11: Corrected PO export

**What**

安全に一意の修正を決定できる指摘について、利用者はその修正を反映した `.po` ファイルを取得できなければならない。

人による判断が必要な指摘は、自動的に修正してはならない。

**Why**

明確なスタイル違反を手作業で繰り返し修正する負担を減らしながら、機械判定が翻訳者の判断を置き換えることを防ぐため。

### FR-12: Correction result visibility

**What**

修正版 `.po` ファイルを生成した場合、利用者はどの指摘が修正され、どの指摘が未修正のまま残っているか確認できなければならない。

**Why**

自動修正の結果を利用者自身が確認できる状態を維持するため。

### FR-13: Original file preservation

**What**

修正版 `.po` ファイルを生成しても、利用者が入力した元の `.po` ファイルそのものを変更してはならない。

**Why**

利用者が必要に応じて元の翻訳へ戻れる状態を維持するため。

### FR-14: Combined result export

**What**

確認結果に複数の成果物が存在する場合、利用者はそれらをまとめて取得できなければならない。

対象となり得る成果物は以下とする。

- 確認結果レポート
- 修正版 `.po` ファイル

**Why**

関連する成果物を個別に管理する負担を減らし、一回の確認結果を一まとまりとして保存または共有できるようにするため。

### FR-15: Locale-specific rule applicability

**What**

WJTC は、確認対象の翻訳ロケールに適用されるルールだけを使用し、異なるロケールのルールを同じ翻訳に適用してはならない。

**Why**

将来対応する翻訳ロケールが増えても、他のロケール固有の規則による誤った指摘や修正を防ぐため。

## Quality requirements

### QR-01: Translation privacy

**What**

利用者が確認する翻訳内容を、明示された別の要件がない限り外部サービスへ送信してはならない。

**Why**

未公開の翻訳や開発中のプロジェクトを安心して確認できるようにするため。

### QR-02: Correction data integrity

**What**

修正版 `.po` ファイルを生成する場合、WJTC が意図的に修正する対象以外の翻訳情報を失ったり、意味を変更したりしてはならない。

**Why**

スタイル修正によって翻訳ファイルそのものが破損したり、別の翻訳情報が意図せず変更されたりすることを防ぐため。

### QR-03: Deterministic validation

**What**

同じルールの条件下で同じ `.po` ファイルを確認した場合、同じ確認結果を得られなければならない。

**Why**

利用者が WJTC の判定を再現可能な確認結果として利用できるようにするため。

### QR-04: Conservative automatic correction

**What**

自動修正は、WJTC が修正内容を一意に決定できる指摘だけを対象としなければならない。

文脈判断を必要とする指摘を自動修正してはならない。

**Why**

自動修正によって正しい翻訳表現を誤って変更するリスクを抑えるため。

### QR-05: Result comprehensibility

**What**

利用者はスタイルガイドの項目番号や WJTC の内部知識を事前に知らなくても、各指摘の意味と次に確認すべき内容を理解できなければならない。

**Why**

WJTC を翻訳提出前の実用的な確認手段として利用できるようにするため。

## Out of scope for v1

v1 では以下を対象としない。

- 自然な日本語かどうかの評価
- 文脈依存の語調や表現の評価
- `You / Your` の自然な省略判断
- UI ラベルや固有名詞に対する「」の適否判断
- カタカナ長音の高度な判断
- 中点 `・` の文脈依存判断
- AI による文章評価
- 自動翻訳
- 一般的な日本語スペルチェック
- translate.wordpress.org への直接反映
- GlotPress との直接統合
- ブラウザー拡張
- 人による判断が必要な Warning の自動修正
- WordPress 日本語翻訳スタイルガイドそのものの代替
- 日本語（`ja`）以外の翻訳ロケール
- 利用者による翻訳ロケールの選択

WordPress 共通の翻訳チェックについては、WJTC の主要目的とはしない。

実害が大きく、必要性が明確になった項目については、将来別途検討する。

## v1 completion criteria

v1 の要件定義は、少なくとも以下が満たされたとき完了とする。

- v1 の確認対象ロケールが日本語（`ja`）として明記されている
- v1 で確認する日本語翻訳スタイルのルールが確定している
- 各ルールに WordPress 日本語翻訳スタイルガイド上の根拠が存在する
- 各ルールについて Error / Warning の区分が定義されている
- 各ルールについて自動修正可能かどうかが定義されている
- 利用者が確認結果の概要と個々の指摘を理解できる
- 問題がない場合も確認結果を明確に判断できる
- 確認結果をエクスポートできる
- 安全に修正可能な項目について修正版 `.po` ファイルを取得できる
- 自動修正された項目と未修正の項目を確認できる
- 元の `.po` ファイルが変更されない
- 修正対象以外の翻訳情報が失われない
- 複数の成果物をまとめて取得できる
- v1 で扱わない項目が明確になっている
