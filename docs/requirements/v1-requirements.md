# WP Translation Checker v1 requirements

## Purpose

WP Translation Checker（WTC）は、WordPress 日本語翻訳スタイルガイドのうち、機械的に判定可能な項目を `.po` ファイルに対して確認し、翻訳を提出する前に修正候補を把握できるようにする。

WTC は WordPress 日本語翻訳スタイルガイドそのものを置き換えるものではない。

ツールの判定だけで翻訳の正しさを決定するのではなく、各指摘から判定理由とスタイルガイド上の根拠を確認できることを重視する。

## v1 scope

v1 は、日本語固有の翻訳スタイルのうち、機械判定による誤検出を抑えやすい項目を対象とする。

v1 の対象ルールは以下とする。

| ガイド | v1 対象ルール                                                    | Severity |
| ------ | ---------------------------------------------------------------- | -------- |
| 1-1    | 日本語の句読点                                                   | Error    |
| 1-2    | 英数字・記号の半角表記                                           | Error    |
| 1-4    | 半角文字と全角文字の間のスペース                                 | Error    |
| 1-5    | 半角丸括弧と前後スペース                                         | Error    |
| 1-6    | 丸括弧内側の不要スペース                                         | Error    |
| 1-7    | 括弧内末尾の句点                                                 | Error    |
| 1-8    | 文末括弧と句点の位置                                             | Error    |
| 1-9    | 半角数字前後の不要スペース                                       | Error    |
| 3-2    | `View XX` を「〜を表示 (する)」に統一                            | Warning  |
| 3-3    | `XX are/is not allowed to...` を「〜する権限がありません」に統一 | Warning  |
| 3-4    | `Sorry, ...` の Sorry を訳さない                                 | Warning  |
| 3-6    | 「下さい / 全て / 既に」などの推奨表記                           | Error    |

v1 は確認結果の提示と、正常完了した現在の確認結果の共有・再利用を対象とする。入力された `.po` ファイルの修正および修正版ファイルの生成は行わない。

## Locale scope

v1 では、日本語（`ja`）の翻訳スタイルのみを確認対象とする。

WTC は特定の翻訳ロケールに限定しないプロダクトとし、locale ごとのルールセットを追加できる方向を想定する。ただし、v1 の対応ロケールは日本語（`ja`）のみとし、他のロケールのチェックルールおよび利用者によるロケール選択は v1 の対象外とする。

## Severity

WTC は、指摘の確実性を区別できなければならない。

### Error

機械的に高い確度で問題と判断できる指摘。

### Warning

例外または文脈によって正しい可能性があり、人による確認が必要な指摘。

Warning は Error と同等の確実性を持つ指摘として扱わない。

## Functional requirements

### FR-01: PO file validation

**What**

利用者は `.po` ファイルを WTC で確認できなければならない。

**Why**

WordPress の翻訳を提出する前に、実際の翻訳ファイルを対象としてスタイル上の問題を確認できるようにするため。

### FR-02: Invalid input feedback

**What**

入力されたファイルを正常に確認できない場合、利用者は確認を実行できなかったことを認識できなければならない。

**Why**

解析できなかったファイルを問題のない翻訳ファイルと誤認することを防ぐため。

### FR-03: Supported Japanese style checks

**What**

WTC は、v1 の対象として定義された日本語翻訳スタイルのルールについて翻訳を確認できなければならない。

**Why**

提出前に機械的に発見可能なスタイル上の問題を見つけられるようにするため。

### FR-04: Validation result summary

**What**

確認完了後、利用者は確認結果の全体像を把握できなければならない。

少なくとも以下を把握できること。

- 確認が完了したか
- Error の件数
- Warning の件数
- 問題が検出されなかったか

**Why**

個々の指摘を読む前に、翻訳ファイル全体の状態を短時間で判断できるようにするため。

### FR-05: Individual finding identification

**What**

検出された各指摘について、利用者は対象となった翻訳箇所を特定できなければならない。

**Why**

利用者が `.po` ファイル内のどの翻訳を確認または修正すればよいか判断できるようにするため。

### FR-06: Finding explanation

**What**

各指摘について、利用者は以下を理解できなければならない。

- 何が問題として検出されたか
- Error または Warning のどちらであるか
- なぜ指摘されたか

**Why**

単に問題があると通知するだけでなく、利用者自身が修正の必要性を判断できるようにするため。

### FR-07: Style guide traceability

**What**

各チェックルールは、その判断根拠となる WordPress 日本語翻訳スタイルガイドの項目を確認できなければならない。

**Why**

WTC 独自の判断ではなく、スタイルガイドを一次情報として確認できるようにするため。

### FR-08: Clear successful result

**What**

問題が検出されなかった場合、そのことを利用者が明確に認識できなければならない。

**Why**

結果が何も表示されない状態と、正常に確認した結果として問題がなかった状態を区別できるようにするため。

### FR-09: Locale-specific rule applicability

**What**

WTC は、確認対象の翻訳ロケールに適用されるルールだけを使用し、異なるロケールのルールを同じ翻訳に適用してはならない。

**Why**

将来対応する翻訳ロケールが増えても、他のロケール固有の規則による誤った指摘を防ぐため。

### FR-10: Unsupported locale feedback

**What**

WTC が対応していない翻訳ロケールの `.po` ファイルは、正常に確認された結果として扱ってはならず、利用者は対象ロケールが未対応であることを認識できなければならない。

**Why**

未対応ロケールの翻訳を確認済みで問題がないと誤認することを防ぐため。

### FR-11: Result export and copy

**What**

正常に確認が完了した現在の結果について、利用者は以下を行えなければならない。

- CSV 形式で保存する
- JSON 形式で保存する
- Markdown 形式でコピーする

出力対象は常に現在の確認結果全体とし、画面上のフィルターやページネーションによって出力対象が狭められてはならない。

Markdown では翻訳内の具体的なNG箇所を太字で識別できなければならない。一方、CSV / JSON の翻訳文字列には Markdown 等の表示装飾を追加してはならない。

指摘が0件の場合も、正常完了した結果として保存またはコピーできなければならない。

正常に確認できなかった状態や、現在の入力に対応しない古い結果は出力できてはならない。

**Why**

確認結果を表計算ソフト、外部ツール、Issue、PR、チャット等で整理・共有・再利用できるようにしつつ、画面表示上の一時的な絞り込みによって確認結果の一部だけを誤って共有することを防ぐため。

### FR-12: Result filtering by rule

**What**

正常に確認が完了し1件以上の指摘がある場合、利用者は現在の確認結果に含まれるスタイルガイド項目から1つを選び、その項目に該当する指摘だけを表示できなければならない。

初期状態ではすべての指摘を表示し、各スタイルガイド項目について現在の確認結果に含まれる指摘件数を確認できなければならない。

ルールによる絞り込みは指摘一覧の表示だけに作用し、確認結果全体の Error / Warning 件数や保存・コピー対象を変更してはならない。

**Why**

指摘が多い翻訳ファイルでも、利用者が確認したいスタイルガイド項目へ絞って効率よく内容を確認できるようにしつつ、確認結果全体の状態や共有内容を一時的な表示条件と混同しないため。

## Quality requirements

### QR-01: Translation privacy

**What**

利用者が確認する翻訳内容を、明示された別の要件がない限り外部サービスへ送信してはならない。

**Why**

未公開の翻訳や開発中のプロジェクトを安心して確認できるようにするため。

### QR-02: Deterministic validation

**What**

同じルールの条件下で同じ `.po` ファイルを確認した場合、同じ確認結果を得られなければならない。

**Why**

利用者が WTC の判定を再現可能な確認結果として利用できるようにするため。

### QR-03: Result comprehensibility

**What**

利用者はスタイルガイドの項目番号や WTC の内部知識を事前に知らなくても、各指摘の意味と次に確認すべき内容を理解できなければならない。

**Why**

WTC を翻訳提出前の実用的な確認手段として利用できるようにするため。

## Out of scope for v1

WordPress 日本語翻訳スタイルガイドの棚卸しにおいて、v1 対象外または WordPress 共通チェックに分類した項目は以下とする。

| ガイド | 項目                                     | 分類                   |
| ------ | ---------------------------------------- | ---------------------- |
| 1-3    | 原則として半角の算用数字を使用           | v1 対象外              |
| 2-1    | 固有名詞を「」で囲む                     | v1 対象外              |
| 2-2    | メニュー項目・ボタンラベルを「」で囲む   | v1 対象外              |
| 2-3    | 引用内容に応じた引用符の使い分け         | v1 対象外              |
| 2-4    | `<em>` / `<i>` の日本語表現              | v1 対象外              |
| 3-1    | 自然な日本語・受動態回避                 | v1 対象外              |
| 3-5    | `You / Your` の自然な省略                | v1 対象外              |
| 3-7    | メニュー項目・ボタンラベルの訳語の一貫性 | WordPress 共通チェック |
| 3-8    | 見出し / 箇条書き / ボタンの語尾・句読点 | v1 対象外              |
| 4-1    | カタカナ語の長音記号                     | v1 対象外              |
| 4-2    | 合成語への長音ルール適用                 | v1 対象外              |
| 5      | 中点 `・`                                | v1 対象外              |
| 6      | `WordPress` の表記                       | WordPress 共通チェック |
| 6      | 機能名                                   | WordPress 共通チェック |
| 6      | テーマ名・プラグイン名                   | WordPress 共通チェック |
| 7      | 日付・日時の日本語表記                   | v1 対象外              |
| 8      | プレースホルダー                         | WordPress 共通チェック |

WordPress 共通チェックは、日本語固有ルールと区別するために分類を明記するものであり、WTC v1 の主要目的には含めない。

また、v1 では以下を対象としない。

- AI による文章評価
- 自動翻訳
- 一般的な日本語スペルチェック
- 入力された `.po` ファイルの自動修正
- 修正版 `.po` ファイルの生成
- translate.wordpress.org への直接反映
- GlotPress との直接統合
- ブラウザー拡張
- WordPress 日本語翻訳スタイルガイドそのものの代替
- 日本語（`ja`）以外の翻訳ロケール
- 利用者による翻訳ロケールの選択

実害が大きく、必要性が明確になった項目については、将来別途検討する。

## v1 completion criteria

v1 の要件定義は、少なくとも以下が満たされたとき完了とする。

- v1 の確認対象ロケールが日本語（`ja`）として明記されている
- v1 で確認する日本語翻訳スタイルのルールが確定している
- 各ルールに WordPress 日本語翻訳スタイルガイド上の根拠が存在する
- 各ルールについて Error / Warning の区分が定義されている
- 利用者が確認結果の概要と個々の指摘を理解でき、位置を特定できる指摘では翻訳内の具体的なNG箇所を識別できる
- 正常完了した現在の確認結果全体を CSV / JSON で保存し、NG箇所を太字で示した Markdown でコピーできる
- 指摘がある場合、現在の確認結果に存在するスタイルガイド項目ごとに指摘を絞り込める
- 問題がない場合も確認結果を明確に判断できる
- v1 対象外および WordPress 共通チェックの項目が、スタイルガイド上の項目と分類を追跡できる形で明記されている
- v1 で扱わないその他の項目が明確になっている
